# 排错指南

先记下扩展版本、课程号、所选目录、操作步骤、界面错误、扫描栏目和运行记录。不要删 `.bb-downloads` 或清空历史来“修复”，那会失去去重和备份依据。日志和目录包含课程名称、路径、老师链接；对外分享前自行检查，无需提供密码或 Cookie。

## 按症状定位

| 症状 | 检查与处理 |
|---|---|
| 本地助手未连接 / 版本旧 | 运行 `安装助手.command`，再重载扩展。固定 ID 应是 `ifblkamjhaokdephpmkhcinhkgjoedaa`。检查安装器打印的 Python 路径是否仍存在 |
| 点选文件夹没有窗口 | 检查 macOS 是否锁屏，查看是否有被遮挡的“选择课程资料文件夹”窗口。不要连续重复点。选择器最长等待 300 秒，超时后重试；更新安装器会提供标准 `.app` 目录选择器 |
| Chrome 加载目录的“选择”灰色 | 确认选中 `extension` 文件夹；可用 `⌘⇧G` 输入安装器给出的绝对路径。取消后重开；也可手动拖入扩展管理页。不要以导入配置文件替代正常加载 |
| 找不到课程 | 同一 Chrome 配置中登录 BB，打开课程任一资料页，再查找课程。核对课程代码、学期和班级；多配置 Chrome 的登录态不共享 |
| 漏掉 Lecture Notes / Midterm | 确认扩展和助手都是 1.1。重新查找课程、重新扫描；展开“课程结构与链接”核对左栏入口。若提示仅扫描当前入口，表示菜单未识别，不能认为全课完整 |
| 看到“未识别资料列表” | 该入口可能是另一种 BB 页面、脚本加载区或工具。记录栏目名称、页面 URL 与截图；不要把警告等同于该栏目没有附件 |
| Announcements 没下载 | 这是明确规则，该栏目及附件、链接全部忽略，大小写不敏感。Discussions、Groups、Tools、Help 同理 |
| 网站链接没有下载网页 | 这是明确规则。看对应 `链接.md` 和根目录 `课程目录.md`，只保存链接地址，不抓外部网页或外部 PDF |
| 文件显示历史已下载，但目录里找不到 | 可能改名、移动、删除，或人工确认未记录位置。查看 `history.json` 的 savedPath；需要时在预览选“重新下载一份”，原有文件不会覆盖 |
| 手工下载的 `(1)` 文件没被识别 | 首次查重只比较完整文件名，忽略大小写。不做模糊匹配。核实后选“已手动下载，记入历史” |
| 多个同名文件该选哪个 | 比较路径、大小并自行打开核实。下拉框选对应文件；不确定位置可明确只记历史，不会伪造本地链接 |
| 文件大小或格式不符 | 可能登录 HTML、错误页面或服务端内容变化。保留暂存文件，重新登录后重试。不要手动把失败任务标成成功 |
| Chrome 要求人工核实下载 | 在 Chrome 下载列表处理其提示；只有 Chrome 确认安全/接受后助手才归档。不要绕过浏览器安全拦截 |
| 附件成功，目录更新失败 | 看独立的红色记录错误，检查目录写权限、磁盘空间、是否被移动/外置盘断开。修复后点“重试更新目录记录”，不会重新下载成功附件 |
| Markdown 出现备份 | 表示检测到用户修改；你的原文在 `*.用户修改备份-标识.md` 中。助手不会自动把个人笔记合并回新目录 |
| 生成了 `课程目录（BB助手）.md` | 原目录已经有同名普通文件。为保护它，助手选择了新名称，面板会显示实际目录文件名 |
| 扫描部分失败 | 警告列出未读到的栏目；其余栏目可继续预览。累计目录保留之前信息，并标注未重新核实。排除登录问题后再次扫描 |
| 更新后旧文件夹还在 | 正常。升级不会重排旧资料，旧位置由记录引用。旧版目录或标题改名留下的生成文件也不会自动删除 |

## 三层诊断

### 1. 面板

展开“查看运行记录”。关键阶段包括找到课程、扫描完成（栏目/唯一附件/链接数量）、目录记录更新、开始下载、逐个保存、结束。警告只代表部分未验证；“0 失败”不代表警告中的栏目已扫描成功。

### 2. Chrome

`chrome://extensions` → BB 助手 → **Service Worker** 或 **错误**。在 `chrome://downloads` 查看传输状态。重载扩展可能关闭其面板；点击工具栏图标重新打开即可。不要在下载活动期间重载。

目录结构仍是旧版：核对“详情”里的扩展加载路径。1.1 安装器更新固定应用目录和源项目，但如果你从另一份解压副本加载，需要重新加载正确副本。

### 3. 本地记录

- `~/Library/Application Support/BB Course Downloader/config.json`：rootId、课程目录、pending token、归档 receipts。
- 课程目录 `.bb-downloads/history.json`：资源 ID、savedPath、manual、completedAt、size、sha256。
- 课程目录 `.bb-downloads/catalog.json`：nodes、files、courses、documents。检查哪些结构来自当前 scanId，哪些来自此前扫描。
- Chrome 默认下载目录 `_BB_Downloads/<token>/`：未归档文件；完成归档后暂存副本被移除。Chrome 历史中“文件已移动”正常。

这些文件是状态依据，不建议手动编辑。JSON 损坏会明确报错并保留原文件，而不是悄悄重建并重复下载。

## 维护者复现

在项目目录执行：

```sh
npm ci --ignore-scripts
npm test
python3 native/install.py --home /private/tmp/bb-installer-check
python3 scripts/package.py
```

测试根目录独立于真实课程；安装器的 `--home` 用于验证文件布局，不修改真正 Chrome 注册。安装器目录副本不是一个能直接登录真实 BB 的测试浏览器。

修改解析器时加入最小 HTML fixture，保留必要 DOM 结构、菜单目标和内容行 ID，替换姓名/课程隐私。至少覆盖：多菜单、排除栏目、子文件夹、内容标题、多附件、外链、纯文字、重复资源、登录页。修改归档/记录时覆盖：不覆盖、用户改名、用户编辑备份、路径越界、符号链接、重复回执、局部扫描。

## 已知边界

Classic HTML 静态资料列表可用；Ultra、脚本动态内容、`bbcswebdav` 以外的下载接口尚未覆盖。仅在资料条目内识别 HTTP(S) 教师链接，忽略菜单控件与常见 Blackboard 操作 URL。若学校改变 HTML 或链接包装形式，需要增加解析 fixture 和适配代码，不能通过放宽所有链接遍历来解决。
